# Anti-Patterns

11 条反模式详细解释 + 升级到用户的格式模板。

## 主 agent 反模式（5 条）

### ❌ AP-1：主 agent 未经决策表确认就亲自写代码
**场景**：跳过决策表直接动手写
**为什么坏**：污染上下文、绕过 Iron Law
**正确做法**：
- 先查 references/decision-matrix.md
- 决策 = 派 → 派 subagent
- 决策 = 不派 → 主 agent 走实现路径（仅此分支）
- 决策表未覆盖 → 不派 + 升级用户

### ❌ AP-2：主 agent 读大文件
**场景**：让主 agent 读 1000 行的 Java 文件
**为什么坏**：污染主 agent 上下文，导致后续决策质量下降
**正确做法**：
- 让 subagent 读大文件
- 主 agent 只读 findings/<task>.md（subagent 写回的精炼版）
- 读大文件前问：是否真的需要主 agent 知道这些细节？

### ❌ AP-3：主 agent 维护"上下文快照"
**场景**：在主 agent 内部用变量记"我们到 Phase 2 了"
**为什么坏**：上下文会被压缩/遗忘，状态不一致
**正确做法**：
- 全部状态写到 plan/task_plan.md
- 主 agent 不维护任何"内部状态"
- 需要时重读 plan

### ❌ AP-4：主 agent 跳过决策表
**场景**："这个任务很明显，直接派"——不查决策表
**为什么坏**：决策不一致，无法审计
**正确做法**：
- 严格按决策表
- 即使是"显然"的决策也查表
- 决策表未覆盖 = 不派 + 升级

### ❌ AP-5：主 agent 在 NEEDS_CONTEXT 时"猜"
**场景**：subagent 说"需要 X 信息"，主 agent 没真补充就重派
**为什么坏**：subagent 还是没 context，循环失败
**正确做法**：
- 真正补充 context
- 重派前确认 subagent 已有足够信息
- 3 次 NEEDS_CONTEXT 后升级用户

## subagent 反模式（3 条）

### ❌ AP-6：subagent 继承主 agent 上下文
**场景**：派 subagent 时不传 context packet，让 subagent 自己读
**为什么坏**：subagent 看到的是"什么都有"的模糊上下文，决策质量差
**正确做法**：
- 主 agent 显式传 context packet（11 字段）
- subagent 不读主 agent 的对话历史
- context packet 是 subagent 的"剧本"

### ❌ AP-7：subagent 跳 TDD
**场景**：subagent 写实现不写测试
**为什么坏**：违反项目铁律
**正确做法**：
- subagent 必读 test-driven-development
- context packet 必含"验证命令"
- 完成后必跑 mvn test

### ❌ AP-8：subagent 不写 findings/
**场景**：subagent 完成后不写返回契约
**为什么坏**：主 agent 无法知道 subagent 做了什么
**正确做法**：
- context packet 必含"返回契约"（3 个必写文件）
- subagent 不写 findings/ = 没完成任务
- 主 agent 必读 findings/ 验证

## 决策表反模式（3 条）

### ❌ AP-9：决策表没覆盖时硬派
**场景**：决策表没对应规则，主 agent 凭感觉"这应该派"
**为什么坏**：决策不一致
**正确做法**：
- 决策表未覆盖 = 不派 + 咨询用户
- 不要硬派
- 把新场景记录到 decisions.md，未来加到决策表

### ❌ AP-10：决策表没覆盖时硬干
**场景**：决策表没对应规则，主 agent "反正简单自己干"
**为什么坏**：跳过决策流程
**正确做法**：
- 决策表未覆盖 = 不派 + 咨询用户
- 不要硬干
- 同上

### ❌ AP-11：决策表频繁修正
**场景**：每个新场景都改决策表
**为什么坏**：决策表失去稳定性
**正确做法**：
- 决策表是稳定规范，6 个月内不轻易改
- 临时情况用 decisions.md 记录
- 累积 5+ 个新场景后再统一改

## 升级到用户的格式模板

当主 agent 必须升级时，使用以下格式：

```markdown
## ⚠️ 升级：需要用户决策

### 任务
[任务描述]

### 已尝试
1. **方案 A**：[描述] → [结果]
2. **方案 B**：[描述] → [结果]
3. **方案 C**：[描述] → [结果]

### 失败原因分析
[深度分析：上下文问题/任务太大/设计错误/决策表未覆盖？]

### 建议下一步
- A) 接受当前结果
- B) 让我尝试 [其他方案]
- C) 修改任务定义
- D) 暂停，等待用户输入
```

## 反模式检测清单

在每个 Phase 结束时，主 agent 应该自问：

- [ ] 我是否未经决策表就亲自写代码？（AP-1）
- [ ] 我是否读了大文件污染上下文？（AP-2）
- [ ] 我是否在内部维护状态而不是文件？（AP-3）
- [ ] 我是否跳过了决策表？（AP-4）
- [ ] 我是否在 NEEDS_CONTEXT 时没真补充？（AP-5）
- [ ] 我派 subagent 时是否传了完整 context packet？（AP-6）
- [ ] subagent 是否遵循 TDD？（AP-7）
- [ ] subagent 是否写了 findings/？（AP-8）
- [ ] 决策表未覆盖时我是否硬派了？（AP-9）
- [ ] 决策表未覆盖时我是否硬干了？（AP-10）
- [ ] 我是否频繁改决策表？（AP-11）

如果任何一项是，停下来，按反模式修正。
